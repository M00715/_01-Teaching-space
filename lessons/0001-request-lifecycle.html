从浏览器到数据库：一次 CRUD 请求的生命周期

Spring Boot CRUD 复习 · 第 1 课 / 共约 6 课 · 预计 20 分钟

🎯 本课服务于 MISSION.md：能凭记忆口述「一次请求从浏览器到数据库的完整链路」。这是把 IoC / AOP / Mapper 等零散名词串成一张地图的第一块拼图。

一、先建立全景：一条请求怎么走完

你以前记过一堆名词，但没把它们连成一条线。本课只做一件事：把四个名词按「请求流动的顺序」排成一列。记住这条线，后面每一课都是往这条线上挂细节。

浏览器
你/前端
发起 HTTP 请求
→
Controller
控制层
接请求、收参数
→
Service
业务层
写业务逻辑
→
Mapper
数据层
拼 SQL、访数据库
→
DB
SQLite
真正存数据

返回时原路倒流：DB 给结果 → Mapper 转成 Java 对象 → Service 加工 → Controller 转成 JSON → 浏览器收到响应。整条链路就是「基础 CRUD」四个字拆开的全部含义。

二、四个角色，各管一摊

Controller 控制层

注解：@RestController

对外门面。负责「接住请求、读懂参数、返回 JSON」。不写业务，只做转发。

Service 业务层

注解：@Service

真正干活的地方。增删改查的规则、校验、事务都在这里。

Mapper 数据层

注解：@Mapper

MyBatis 的接口。一个方法对应一条 SQL，把 Java 对象和数据表互相映射。

DB 数据库

本项目：SQLite

数据的归宿。你写的 SQL 最终在这里执行。MySQL 与 SQLite 的 CRUD 语句几乎一致。

💡 Aha：为什么这些名词能连起来？
你记得 Spring 的 IoC（控制反转）吗？它的意思是：这些对象不是你 new 出来的，而是 Spring 帮你创建好、再「注入」到需要用它的地方。所以 Controller 里能直接用一个 Service，Service 里能直接用一个 Mapper——你从没手动实例化它们。正是 IoC 把这条链路上的四个角色「粘」在了一起。AOP 是另一回事（给方法统一加日志/事务），先记住 IoC 即可。

🔧 澄清卡片 · 最容易混淆的两个点

① 每一层的 @Autowired 到底装的是什么？

装配方向 = 调用方向，逐层向下：Controller 依赖 Service，Service 依赖 Mapper。谁调用谁，谁就注入谁。

@RestController // ← 这是一个 Spring Bean public class UserController { @Autowired private UserService userService; // Controller 注入 Service（不是 Mapper） public User create(User user) { return userService.save(user); // 调 Service，自己不碰 DB } } @Service // ← 这也是一个 Bean public class UserService { @Autowired private UserMapper userMapper; // Service 注入 Mapper 接口 public User save(User user) { userMapper.insert(user); // 调接口，MyBatis 去跑 SQL return user; } } @Mapper // ← 接口本身 = Bean（MyBatis 生成代理并注册） public interface UserMapper { void insert(User user); }

② 为什么 Controller 不直接 @Autowired Mapper？

  1. 技术上能写、能跑，但不该这么写。分层的目的就是各管一段：Controller 管「接请求/回 JSON」，Service 管「业务/校验/事务」，Mapper 管「SQL」。Controller 越过 Service 直接调 Mapper，等于让门面去干数据访问的活，事务和校验就没地方放了。
  2. 严格分层下，Controller 只注入 Service。
  3. @Autowired 凭什么能把一个「接口」注入进来？靠 @Mapper（或启动类上的 @MapperScan）。MyBatis 启动时扫描这些接口，用动态代理生成实现类并注册成 Spring Bean——所以接口也能被注入。

📌 现代写法推荐构造器注入（依赖写在构造参数里，可省略 @Autowired）：依赖不可变、好测试。第 2 课骨架里会直接示范。
