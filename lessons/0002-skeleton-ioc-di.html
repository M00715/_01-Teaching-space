二、IoC/DI 是怎么落地的

第 1 课说「IoC 把四个角色粘在一起」。落地时靠两件具体的事：

  1. Mapper 接口怎么变成 Bean？ 看 Application.java 上的 @MapperScan("learn.springboot.mapper")。Spring 启动时扫描这个包下的接口，MyBatis 为每个接口生成动态代理，并注册成 Spring 容器里的 Bean。所以 UserMapper 能被注入——虽然你从没写它的实现类。
  2. 层与层怎么连起来？ 用构造器注入：UserService 的构造参数写着 UserMapper，Spring 自动把上面那个代理塞进来；UserController 的构造参数写着 UserService，Spring 再把 Service 塞进来。装配方向 = 调用方向，逐层向下，和第 1 课澄清卡片完全一致。

🔧 为什么用构造器注入，而不是字段 @Autowired？

字段注入（在字段上写 @Autowired private UserService userService;）能跑，但有两个缺点：依赖可被人改（非 final）、单元测试时很难塞一个假的 Mapper 进去。构造器注入把依赖写在参数里、声明成 final，既不可变又好测。这是现在 Spring 官方推荐写法。

三、四块代码逐个看

① 实体 User.java

package learn.springboot.entity; import lombok.Data; @Data // 自动生成 getter/setter/toString public class User { private Long id; private String name; private String email; }

② 数据层 UserMapper.java（只有接口 + 注解）

public interface UserMapper { @Insert("INSERT INTO user(name, email) VALUES(#{name}, #{email})") @Options(useGeneratedKeys = true, keyProperty = "id") void insert(User user); // 自增主键回填到 user.id @Select("SELECT * FROM user WHERE id = #{id}") User findById(Long id); @Select("SELECT * FROM user") List<User> findAll(); @Update("UPDATE user SET name=#{name}, email=#{email} WHERE id=#{id}") void update(User user); @Delete("DELETE FROM user WHERE id=#{id}") void deleteById(Long id); }

③ 业务层 UserService.java（构造器注入 Mapper）

@Service public class UserService { private final UserMapper userMapper; public UserService(UserMapper userMapper) { // 构造器注入 this.userMapper = userMapper; } public User create(User user) { userMapper.insert(user); return user; // 此时 user.id 已有值 } // findById / findAll / update / delete 同理…… }

④ 控制层 UserController.java（构造器注入 Service）

@RestController @RequestMapping("/users") public class UserController { private final UserService userService; public UserController(UserService userService) { this.userService = userService; } @PostMapping // POST /users public User create(@RequestBody User user) { // JSON→对象 return userService.create(user); } // GET /users/{id} GET /users PUT /users/{id} DELETE /users/{id} }

四、让它能跑起来

我在 _01 里已经把上面四个文件和建表脚本都建好了。还改了两处配置：

  • pom.xml：加了 spring-boot-starter-web（提供 @RestController 和内嵌 Tomcat，REST 必需）。
  • application.yaml：加了 spring.sql.init.mode=always，启动时自动执行 src/main/resources/schema.sql 建好 user 表。
# 在项目根目录 _01 下启动（需要 Maven 联网拉一次依赖） mvn spring-boot:run # 启动后试一条新增： curl -X POST localhost:8080/users -H "Content-Type: application/json" \ -d "{\"name\":\"张三\",\"email\":\"z@s.com\"}" # 返回 {"id":1,"name":"张三","email":"z@s.com"} 即成功
⚠️ 常见坑：Postman 报 415 Unsupported Media Type
因为 @RequestBody 要求请求体是 JSON（Content-Type: application/json）。 若 Postman 的 Body 选了 form-data（multipart/form-data），Spring 反序列化不了，就回 415。
✅ 正确做法：Body → raw → JSON，填 {"name":"张三","email":"z@s.com"} （不要填 id，自增主键由数据库生成后回填）。
📌 记牢区别：@RequestBody 收 JSON 体；表单数据要用 @RequestParam / @ModelAttribute； 400 是"内容本身有问题"，405 是"HTTP 方法不对"。
💡 改了代码却不生效？多半是没重启
Spring Boot 默认不热加载源码：你改了 .java，但还在跑的那个进程加载的是旧的编译类。 典型表现就是「字段加了但 JSON 里没有」「逻辑改了但行为没变」。
✅ 每次改完 Java 代码，Ctrl+C 停掉 mvn spring-boot:run 再重新跑。 想免去手动重启，可加 spring-boot-devtools 依赖实现自动重启（开发期常用）。
