一、问题：写死的 SQL 不灵活

条件查询僵化

现在的 findByNameLike

@Select("SELECT * FROM user WHERE name LIKE ...")
只能按名字查。想加"年龄区间""邮箱模糊"就得再写新接口，SQL 越写越多、越来越像复制粘贴。

批量操作别扭

现在的 deleteByIds

想 DELETE ... WHERE id IN (1,2,3)，用注解拼 IN 列表很麻烦，容易写成字符串拼接（还有 SQL 注入风险）。

痛点一句话：真实的查询几乎都是"可选条件组合"——传了 name 就按 name 查、传了年龄就加年龄、都没传就查全部。写死的 SQL 做不到，动态 SQL 就是为此而生。

二、从注解 @Select 到 XML 映射文件

你之前一直用 @Select("...") 注解写 SQL——它适合短、固定的 SQL。一旦 SQL 要"根据参数动态拼"，注解里塞一堆 <if> 会非常难看，这时要用 XML 映射文件。

🔧 XML 文件长什么样

<!-- resources/mapper/UserMapper.xml --> <?xml version="1.0" encoding="UTF-8"?> <!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd"> <mapper namespace="learn.springboot.mapper.UserMapper"> <!-- id 必须和接口方法名一致 --> <select id="findByCondition" resultType="learn.springboot.entity.User"> SELECT * FROM user <where> <if test="name != null and name != ''"> AND name LIKE CONCAT('%', #{name}, '%') </if> <if test="ageMin != null"> AND age >= #{ageMin} </if> </where> </select> </mapper>

三个对应点：① namespace = Mapper 接口全限定名；② <select id="..."> 的 id = 接口方法名；③ resultType = 返回的行映射成的类。接口里写方法签名，SQL 写在 XML，MyBatis 按 id 把两者绑起来。

🔧 还要告诉 MyBatis 去哪找 XML

在 application.yml 加（若还没有）：

mybatis: mapper-locations: classpath:mapper/*.xml

（你之前的 SQL 全在注解里，所以一直没配这个。改用 XML 后必须配，否则 MyBatis 找不到 XML 里的 SQL。）

三、<if> + <where>：条件"按需拼接"

这是动态 SQL 的主力。<if test="..."> 里的 test 是 OGNL 表达式（很像 Java 的判断），条件为真才把这段 SQL 拼进去。

// Mapper 接口：参数用 Map 或专用 DTO 都行 List<User> findByCondition(@Param("name") String name, @Param("ageMin") Integer ageMin);

<where> 的智能之处：它会自动去掉首个被拼进去的条件前面的 AND/OR。上面例子里，若只传了 ageMin，拼出来是 WHERE age >= ?（前面那个 AND 被吃掉了）；若啥都没传，<where> 整体不生成，变成 SELECT * FROM user 查全部。你不用手动判断"该不该加 AND"。

🔍 对比写死 SQL：以前要写 findByName、findByAge、findAll 三个接口；现在一个 findByCondition 全包，传什么查什么。

四、<foreach>：批量操作的利器

遍历一个集合，拼成 (1,2,3) 这种形式。最经典的用法就是"按 id 列表批量删除/查询"。

<!-- 批量删除：DELETE FROM user WHERE id IN (1,2,3) --> <delete id="deleteByIds"> DELETE FROM user WHERE id IN ( <foreach collection="ids" item="id" open="(" close=")" separator=","> #{id} </foreach> ) </delete>

collection = 集合参数名（用了 @Param("ids") 就写 "ids"）；item = 遍历出的单个元素名；open/close = 首尾包裹符；separator = 元素间分隔符。最终拼成 IN (1,2,3)。用 #{} 占位，MyBatis 会预编译，天然防 SQL 注入——比自己拼字符串安全太多。

五、<set>：动态更新，避免把没传的字段置 NULL

改用户资料时，客户端往往只传"要改的字段"。用 <set> 只更新传了的字段，没传的保持原值，不会手滑把 email 设成 NULL。

<update id="updateSelective"> UPDATE user <set> <if test="name != null">name = #{name},</if> <if test="age != null">age = #{age},</if> <if test="email != null">email = #{email},</if> </set> WHERE id = #{id} </update>

<set> 会自动剔除末尾多余的逗号（比如只改 name，生成 SET name = ? 而不带尾逗号）。这正好呼应第 6 课"update 用 DTO、字段可空"的设计——哪些字段要改，由前端传不传决定。

六、在 _01 里动手（可选 · 进阶）

  1. 配 XML 路径：application.yml 加 mybatis.mapper-locations: classpath:mapper/*.xml。
  2. 建 XML：resources/mapper/UserMapper.xml，namespace 指向现有 UserMapper 接口。
  3. 搬 SQL：把 findByNameLike 改写成 <if>+<where> 的条件查询；把 deleteByIds 改写成 <foreach> 版本。
  4. 接口签名：条件查询方法加 @Param；批量删除参数改为 @Param("ids") List<Long> ids。
  5. 重启验证：GET /users?name=张 按名查；POST /users/batch 传 [1,2,3] 看批量删除是否只删这三条。
📌 提醒：动态 SQL 本质是"把你已经会的条件判断，从 Java 代码搬到 XML 里用标签表达"。它不难，关键是记住四个标签各管什么：<if> 判断、<where> 智能去 AND、<foreach> 遍历集合、<set> 智能去逗号。
