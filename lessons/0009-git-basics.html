二、Git 三大区域模型（本课骨架）

一切 Git 操作都绕不开这三个本地区域，再加一个远端。记住这张图：

工作区
你看到的文件夹
git add →
暂存区
待提交清单
git commit →
版本库
永久提交历史
git push →
远程仓库
GitHub 服务器
  • 工作区：你日常编辑的文件（src/、pom.xml）。
  • 暂存区（Stage）：git add 把改动"搬"到这里，相当于"我打算提交这些"。
  • 版本库（Repository）：git commit 把暂存区打包成一次快照，永久存进历史。
  • 远程仓库：GitHub 那台服务器，git push 把本地历史传上去。

🔧 一个关键认知

被 .gitignore 忽略的（target/、*.sqlite、.idea/）永远不会进暂存区——所以你 git status 看不到它们，git add . 也加不进去。

三、提交三板斧：add → commit → push

改完代码后每次都用这三步。commit 是追加，不是覆盖——这是新手最该刻进脑子的一点。

# 1. 看哪些文件改了、哪些被忽略（提交前必看） git status # 2. 把改动加入暂存区（. 表示当前目录全部；也可 git add 文件名 单文件） git add . # 3. 生成一次永久提交，-m 后面是说明 git commit -m "描述这次改了啥，如：增加年龄字段校验" # 4. 同步到 GitHub（同样是追加，历史只增不减） git push
为什么"追加不是覆盖"？每次 commit 都在历史链条末尾接一个新节点，旧节点原封不动保留（随时 git log 能看到、能退回）。所以你永远不用担心"提交会把之前搞丢"——这和"保存文件会覆盖原文件"完全不同。

四、分支与远程：master/main、origin 是什么

分支 branch

并行的时间线

git init 默认分支叫 master；GitHub 现在默认叫 main。推送前用 git branch -M main 改名对齐，避免两边名字不一致。

origin

远程地址的"外号"

origin 只是你本地给远程 URL 起的别名，存在 .git/config。改地址用 git remote set-url origin 新地址——不用去 GitHub 网站改。

-u 上游

记住跟踪关系

git push -u origin main 第一次设好"上游"，之后直接 git push 即可，不用每次写 origin main。

五、强推陷阱：你刚踩的坑（本课重点）

你做了 git commit --amend 改写了上次提交，再 git push 被拒——这正是 B 类盲区（不懂"为什么"）。机制如下：

# 正常：每次 commit 在历史末尾接新节点 A → B → C # C 是最新提交 # amend：把"紧挨着的上一次"提交替换成新内容（哈希变了） A → B → C' # C' 替换了 C，旧 C 没了 # 如果 C 之前已经 push 到 GitHub，远端是 A→B→C # 你本地是 A→B→C' → 两边历史对不上 → 普通 push 被拒： # ! [rejected] main -> main (non-fast-forward) # 解决：强推覆盖远端历史（仅限你独自开发的安全场景） git push --force-with-lease origin main
铁律：--amend 会改写历史。规则是——已经 push 到 GitHub 的提交，不要 amend（会造成本地/远端对不上，得强推对齐）。只有"刚提交完、还没 push、发现小错"才用 amend 救场。强推用 --force-with-lease 比裸 --force 稳，万一远端被别人改过它会拒绝，不盲目覆盖。

🔧 你现在的实际处境

你 learn_02 之前 push 失败是因为仓库名写错（learn-02-crud 少了 -demo-），不是强推问题。后来你 amend 过一次，所以现在若 GitHub 上已有旧提交，git push 会 non-fast-forward。先 git remote -v 确认地址是 learn-02-crud-demo.git（无尾杠），再 git push --force-with-lease origin main 强推即可。
