# AI 应用后端（Java）学习路线图 · 总导航

> 这是你整个大专阶段的**总导航文件**，不是某一课的笔记。
> 定位：从 `_01` 的 Spring Boot 地基，走到能投「AI 应用后端岗」的三年竞争力底线（L2）。
> 最后更新：2026-10-20

---

## 0. 一句话背景

- 身份：**大专（专科）在校生，大一**。
- 硬约束：**专升本必考**（已定）。
- 目标职业：**AI 应用后端开发工程师（Java 方向）** → 路线 Spring Boot 地基 → Spring AI → RAG → Agent。
- 兜底要求：即便升本失败，也不至于立即失业 → 所以路线设了**保命线（L0）+ 竞争力底线（L2）双保险**。
- 行业判断（2026-10 联网核实）：Java + AI 复合岗是蓝海，薪资溢价 30–50%、供不应求；**纯 CRUD 型 Java 后端是红海**，正被 AI 编码工具和新人双向挤压。→ 结论：路线正确，但必须冲到「复合」而非停在 CRUD。

## 1. 能力分层 L0–L3

把三年要掌握的本领分成四层。**L0 是保命线，L2 是你给自己定的三年竞争力底线（硬门槛），L3 是上限。**

| 层级 | 名称 | 你要达到的状態 | 核心组成 | 出口信号 |
|---|---|---|---|---|
| **L0** | 生存兜底（保命线） | 万一升本失败，也能投中小厂初级 Java 岗，不失业 | `_01` 全套 CRUD（深度掌握）+ Git/GitHub + Docker 基础 | 见 §3 双闸门 |
| **L1** | 过渡 | 会用 Spring AI 调大模型、写工具调用，搭出最小 AI 后端 | Spring AI 2.0（ChatClient / @Tool / Advisor）、Prompt 与上下文概念 | 独立写出带 @Tool 的对话接口 |
| **L2** | **三年竞争力底线（硬门槛）** | 大专三年应达标，投 AI 应用后端岗的硬门槛 | Spring AI **+ RAG 全链路**（切片/向量化/检索/重排）+ 工程素养（Git/Linux/Docker/MySQL/Redis/单元测试/日志排查）+ Spring Security（JWT 鉴权） | 独立搭一个 RAG 小项目并讲清每段 |
| **L3** | 上限 | 考上本科后冲大厂 / Agent 工作流 | 多智能体编排、云原生（Spring Cloud / K8s）、Agent 工作流 | 能设计多 Agent 协作系统 |

> **关键认知**：L2 不是「上限目标」，是你定的**底线**。L0 只是「万一」的兜底，真正要冲的是 L2。兜底逻辑不变——L0 不丢，但目标抬高。

## 2. 严格顺序闸门（先打透再进下一关）

地基没打透，后面全是空中楼阁。顺序**不可跳跃**：

```
① 收尾 _01 七课 + 自重写 CRUD 项目
        │  （出口 = §3 深度+独立双闸门）
        ▼
② Git + GitHub 推送教程        （把 _01 push 上去）
        ▼
③ Docker 基础                  （把 _01 容器化跑起来）
        ▼
④ L1：Spring AI 基础           （ChatClient / @Tool / Advisor）
        ▼

```

> 注意：Git / Docker 虽被列在 L2 的「工程素养」里，但作为**地基工具提前在 ①②③ 阶段学会**——它们是后面所有项目托底用的，越早会越省事。

## 3. `_01` 出口标准（最重要的一关：深度 + 独立双闸门）

> 你昨天的核心担心：「七课讲完 ≠ 真会，脱离 AI 我写不出异常/分页/全局处理。」
> 解法：**把出口从「课讲完」改成「深度 + 独立」双闸门。** 两关都过，才算 `_01` 打透。

### 闸门 A —— 闭卷实战（脱离 AI 自重写）
- 关掉 AI 辅助，**独立**写出一个完整 CRUD 项目，必须包含：
  - DTO + Bean Validation 入参校验
  - 手写分页（LIMIT/OFFSET + COUNT）
  - 全局异常处理（`@RestControllerAdvice`）
  - MyBatis 动态 SQL（`<if>/<where>` 等）
- 写完交 AI review（契合「引导不替改」约定：你写、AI 查，AI 不动你的代码）。

### 闸门 B —— 口述机制（能讲清「为什么」，不只「怎么写」）
能用自己的话讲清以下四点（不需要写代码，但必须真懂）：
1. `@RestControllerAdvice` + `@ExceptionHandler` **为什么能兜住**全项目的异常？（AOP 横切 + 最具体优先）
2. **checked / unchecked 异常**区别？什么时候该自己 `throw`？
3. 分页里 `LIMIT/OFFSET` **到底在算什么**？`OFFSET = (page-1)*size` 怎么来的？
4. MyBatis-Plus **把 raw MyBatis 的哪一层抽象掉了**？（让你明白 MP 只是语法糖，不是黑魔法）

> 区分两类「不会」：
> - **A 类：记不住具体 API/语法**（如 MP 方法名、分页 SQL 写法）→ 连工作 5 年的人也靠查，**正常，不算不会**。
> - **B 类：不懂背后机制/为什么**（如异常体系、为何全局处理能兜）→ **危险，必须治**。
> 双闸门专门逼你跨过 B 类。

### 两处已决定新增的模块（补你的具体缺口）
| 缺口 | 放哪 | 内容 |
|---|---|---|
| **异常机制概念**（B 类缺口） | `_01` 第 8 课「异常机制概念课」 | 不讲代码，讲**异常体系**（Throwable / Error / Exception、checked vs unchecked、throw/catch 心智模型）+ 为什么全局处理能兜。懂了就能默写。 |
| **Spring Security** | 从「以后再说」**提前到 L1 之前必学入门** | JWT + 拦截器鉴权基础。原 MISSION.md 把它列为 out-of-scope，但你的职业目标需要，故提前。 |

## 5. 关键风险点与兜底逻辑

1. **纯 CRUD 红海风险**（最高优先级）
   - 只停留在 L0，会被 AI 编码工具 + 新人双向挤压，求职困难。
   - 对策：**强制冲 L2**，把「AI + Java 复合」当护城河。

2. **升本兜底逻辑**
   - L0 是「保命线」：万一升本失败，至少能投中小厂初级 Java 岗。
   - 但 L0 **不是目标**，只是兜底；真正目标是 L2。两者不矛盾——L0 不丢，目标抬高。

3. **AI 依赖 B 类风险（你自己的盲区）**
   - 记不住 API（A 类）正常；**不懂机制（B 类）危险**——会变成 AI 的提线木偶。
   - 对策：§3 双闸门（闭卷 + 口述）强制脱钩；第 8 课专攻异常机制。

4. **地基不牢就冲上层**
   - 对策：§2 顺序闸门不可跳跃；`_01` 双闸门没过，不进 Git/Docker/L1。

## 6. 学习节奏与约定

- **引导不替改（仅 `_01` 项目）**：你写代码、AI 做 review 与思路引导；**只有当你明确说「帮我改 / 直接改」时，AI 才动手改 `_01` 代码**。其它项目不受此限。
- **检索 + 间隔复习**：每课结尾有小测，跨课有回忆题，用「费力提取」建长期记忆（契合你的偏好）。
- **文档无限制**：AI 可主动建 md / 路线图 / 学习笔记——**不存在「不主动建文档」的限制**（此误设限制已于 2026-10-19 由你纠正删除）。
- **节奏建议**：地基阶段（①–③）求「透」不求「快」；双闸门没过就慢下来，不要赶课。
